## ۲. ناوبری

نوار شناور پایین (Dock) با ۴ تب + دکمه + وسط (پرتکرارترین کار = ثبت سریع). Dock فقط روی ۴ صفحه ریشه است؛ صفحه‌های داخلی دکمه برگشت دارند:

```
[خانه]  [تراکنش‌ها]  ( + )  [حساب‌ها]  [بیشتر]
```

> تفاوت با Finora: تب‌های Card/Transfer/Account آن‌جا برای بانک است؛ این‌جا «ثبت» مهم‌ترین کار است، پس وسط و با رنگ لیمویی.

### نقشه صفحات

```
قفل برنامه (PIN / اثرانگشت)
شروع اولیه
 ├─ O1 خوش‌آمد (یک صفحه)
 ├─ O2 تنظیم رمز + اثرانگشت
 ├─ O3 دسترسی پیامک (توضیح + رد کردن ممکن)
 └─ O4 افزودن اولین حساب

① خانه  H1
 ├─ ← صف بررسی پیامک  T5
 └─ ← نزدیک‌ترین تعهد  L2 / D2

② تراکنش‌ها  T1
 ├─ T2 فیلتر (bottom sheet)
 ├─ T3 جزئیات تراکنش
 └─ T5 صف بررسی پیامک

(+) ثبت سریع  T4 (bottom sheet: هزینه | درآمد | انتقال)

③ حساب‌ها  A1
 ├─ A2 جزئیات حساب
 │    ├─ A4 انتقال بین حساب‌ها
 │    ├─ گردش حساب (= T1 با فیلتر حساب)
 │    └─ S2 الگوی پیامک این حساب
 └─ A3 افزودن/ویرایش حساب و کارت

④ بیشتر  M1
 ├─ وام و اقساط      L1 → L2 جزئیات (جدول اقساط) → L3 افزودن
 ├─ بدهی و طلب       L4 (تب: بدهکارم | طلبکارم)
 ├─ اهداف پس‌انداز    G1 → G2 جزئیات → G3 افزودن
 ├─ اشخاص            P1 → P2 جزئیات شخص (مانده + تاریخچه)
 ├─ دنگ              D1 گروه‌ها → D2 جزئیات گروه (هزینه‌ها، مانده‌ها، تسویه) → D3 هزینه گروهی
 ├─ دسته‌بندی‌ها      C1
 ├─ قوانین هوشمند     C2 → C3 ویرایش قانون (اگر … و/یا … ← آن‌گاه …)
 ├─ بانک‌ها و الگوها   S1 → S2 ساخت الگو از نمونه پیامک → S3 اسکن پیامک‌های قدیمی
 ├─ پشتیبان و انتقال  B1 (خروجی JSON/CSV، ورودی JSON/CSV)
 ├─ امنیت            X1
 └─ تنظیمات          X2
```

## ۳. صفحات کلیدی

### H1 خانه
از بالا به پایین:
1. **هدر گرادیانی** (آبی روشن ← سرمه‌ای): آواتار + «سلام …»، دکمه چشم (پنهان‌کردن مبالغ)، آیکون پیام با badge تعداد پیامک‌های در انتظار.
2. **موجودی کل** (جمع همه حساب‌ها) با عدد بزرگ؛ «تومان» کم‌رنگ (مثل `.28` در Finora).
3. **دو دکمه قرصی**: ثبت هزینه / ثبت درآمد (دایره لیمویی). انتقال از دکمه + (سگمنت سوم sheet).
4. **کاروسل حساب‌ها**: کارت‌های کوچک شیشه‌ای (بانک، نام، موجودی، ۴ رقم آخر).
5. **کارت شاخص شیشه‌ای**: به ترتیب اولویت یکی از این‌ها: پیامک‌های در انتظار ← نزدیک‌ترین تعهد ← پیشرفت هدف.
6. **کاشی‌های دوتایی**: درآمد ماه (آبی) | هزینه ماه (سرمه‌ای).
7. **کاشی‌های پیشرفت**: پس‌انداز (اهداف) | اقساط پیش رو.
8. **کاشی‌های تعهد**: بدهی‌های پرداخت‌نشده | طلب‌های دریافت‌نشده.
9. آخرین تراکنش‌ها (۵ تا) + «همه».

کارت‌های ماژول ۵ همه این‌جا پوشش داده شده‌اند: موجودی کل، موجودی حساب‌ها، درآمد/هزینه ماه، پس‌انداز، بدهی، طلب، اقساط، نزدیک‌ترین تعهد.

### A2 جزئیات حساب
کارت بزرگ شیشه‌ای (نام بانک، شماره ماسک‌شده، موجودی، زمان آخرین پیامک) قابل swipe بین حساب‌ها ← ردیف دایره‌های عملیات (انتقال، گردش، الگوی پیامک، ویرایش) ← کاشی‌های «هزینه این ماه / درآمد» با نوار پیشرفت ← کارت‌های متصل.

### T1 تراکنش‌ها
جستجو ← چیپ‌های فیلتر (همه، هزینه، درآمد، انتقال، حساب ▾، دسته ▾، تاریخ ▾) ← خلاصه ماه شمسی ← گروه‌بندی روزانه. هر ردیف: آیکون دسته، عنوان، **نشان منبع** (دستی / پیامک / اعلان / فایل)، دسته · حساب · ساعت، مبلغ رنگی.
لیست با `LazyColumn` و Paging از Room؛ هیچ‌وقت کل جدول در حافظه نیست.

### T4 ثبت سریع (sheet)
سگمنت نوع ← مبلغ با کیبورد عددی بزرگ (با جداکننده هزارگان زنده و نمایش «حروفی» مبلغ زیرش) ← حساب ← دسته (پیشنهاد آخرین‌ها) ← تاریخ شمسی (پیش‌فرض امروز) ← اختیاری: توضیح، شخص، هدف، عکس رسید.

### T5 صف بررسی پیامک
دکمه «تأیید همه موارد مطمئن» ← کارت هر پیامک: بانک، **امتیاز اطمینان** (سبز ≥۹۰، زرد کمتر)، متن خام، فیلدهای استخراج‌شده، دسته پیشنهادی قانون، دکمه‌های تأیید / ویرایش / رد. موارد ناشناخته ← «ساخت الگو».

### D2 گروه دنگ
لیست هزینه‌ها (پرداخت‌کننده، سهم‌ها) ← مانده هر نفر ← «پیشنهاد تسویه» با کمترین تعداد انتقال ← ثبت تسویه = تراکنش واقعی روی حساب.

### C3 ویرایش قانون
`اگر` [فرستنده | پذیرنده | متن | مبلغ | حساب] [شامل | برابر | بزرگ‌تر | Regex] [مقدار] (و/یا …) ← `آن‌گاه` [دسته = …] [شخص = …] [توضیح += …] [نادیده بگیر]. اولویت با ترتیب drag. اصلاح دستی دسته یک تراکنش ← پیشنهاد «همیشه این کار را بکن؟» ← قانون جدید.

## ۴. جریان پیامک

```
SMS یا اعلان بانکی رسید
  → SmsReceiver (goAsync، بدون سرویس) / NotificationListener (فقط بسته‌های بانکی)
  → نرمال‌سازی (ارقام فارسی/عربی، حذف ٬ و , بین ارقام، نیم‌فاصله)
  → تشخیص بانک: فرستنده یا اسم بسته در لیست؟ وگرنه امضای متن (مثل «bki. ir»)؟ نه ← تمام
  → هش (بانک + متن نرمال‌شده) ← تکراری؟ تمام
  → فیلدهای قالب آن بانک: نوع، مبلغ، مانده، تاریخ، ۴ رقم کارت، شماره حساب، توضیح
  → تطبیق حساب: ۴ رقم کارت ← شماره حساب ← «تنها حساب این بانک» ← نامشخص
  → تطبیق مانده: مانده قبلی − مبلغ = مانده جدید؟ مطابق ← اطمینان بالا؛ نامطابق ← هشدار شکاف
  → اجرای قوانین (دسته، شخص…)
  → امتیاز اطمینان
      ≥ آستانه کاربر و حساب پیدا شد ← ثبت مستقیم (اختیاری) یا صف
      کمتر ← صف بررسی
پیامک رمز پویا / تبلیغاتی ← قالب «نادیده» ← ذخیره نمی‌شود
```

قالب‌ها در `assets/banks/*.json` و جزئیات هر بانک در [`BANK-FORMATS.md`](BANK-FORMATS.md) است. فعلاً **کشاورزی** و **بلو** با نمونه واقعی تست شده‌اند. کاربر می‌تواند فایل قالب import کند یا از روی نمونه بسازد (S2: علامت‌زدن مبلغ و مانده روی متن ← ساخت الگو).

## ۵. مدل داده

همه مبالغ `Long` به ریال. همه زمان‌ها `Long` epochMillis. `id` همه جداول `Long` autoincrement.

| جدول | فیلدهای اصلی |
|---|---|
| `account` | name, type (BANK/CASH/WALLET), bankCode?, accountNo?, initialBalance, color, archived, sortOrder |
| `card` | accountId, last4, panMasked?, label |
| `category` | name, kind (EXPENSE/INCOME/SAVING/INVEST), parentId?, icon, color, sortOrder |
| `txn` | type (EXPENSE/INCOME/TRANSFER/ADJUST), amount, accountId, toAccountId?, categoryId?, personId?, goalId?, loanId?, splitGroupId?, merchant?, note?, refNo?, balanceAfter? (مانده طبق پیامک، برای تطبیق), occurredAt, source (MANUAL/SMS/NOTIF/IMPORT), rawMessageId? |
| `raw_message` | sender, body, receivedAt, hash (unique), status (PENDING/ACCEPTED/REJECTED/IGNORED), parsedJson, confidence |
| `bank_template` | bankCode, json (همان قالب فیلدی BANK-FORMATS)، priority, userDefined — قالب‌های داخلی از assets خوانده می‌شوند و فقط قالب‌های کاربر این‌جا ذخیره می‌شوند |
| `rule` | name, matchMode (ALL/ANY), conditionsJson, actionsJson, priority, enabled |
| `attachment` | txnId, filePath |
| `person` | name, phone?, cardNo?, bank?, note? |
| `loan` | kind (LOAN/DEBT/RECEIVABLE), personId?, title, principal, interestRate?, startAt, installmentCount?, accountId? |
| `installment` | loanId, dueAt, amount, paidTxnId? |
| `goal` | title, target, dueAt?, priority, monthlyPlan?, status |
| `split_group` | title, kind (TRIP/FRIENDS/HOUSE) |

| `split_expense` | groupId, payerPersonId?, amount, txnId?, title, at |

**موجودی حساب ذخیره نمی‌شود**؛ `initialBalance + جمع تراکنش‌ها` با یک کوئری ایندکس‌دار محاسبه می‌شود ← هیچ‌وقت ناهمخوان نمی‌شود. «تعدیل موجودی» = تراکنش `ADJUST`.

## ۷. قوانین باتری و RAM (غیرقابل مذاکره)

1. **صفر Foreground Service.** پس‌زمینه فقط: `SmsReceiver`، `NotificationListener` (پیش‌فرض خاموش)، یک `PeriodicWorkRequest` روزانه برای یادآور قسط/هدف.
2. هیچ polling، هیچ شبکه (اپ اصلاً `INTERNET` نمی‌خواهد).
3. **بدون blur زنده.** حالت «شیشه‌ای» = گرادیان ثابت + خط دور سفید کم‌رنگ. `Modifier.blur`/RenderEffect ممنوع.
4. لیست‌ها فقط `LazyColumn` + Paging؛ داشبورد با کوئری‌های تجمیعی SQL، نه محاسبه در Kotlin.
5. آیکون‌ها vector drawable تکی؛ کتابخانه `material-icons-extended` ممنوع (چند مگ).
6. R8 + shrinkResources روشن؛ Baseline Profile برای استارت سریع.
7. بدون Firebase، Analytics، Crashlytics.
8. اسکن پیامک قدیمی فقط با دکمه، صفحه‌به‌صفحه، با امکان لغو.

## ۸. وضعیت

- **فاز ۱:** انجام شد (۱۰ آبان ۱۴۰۵).
- **فاز ۴:** انجام شد. اشخاص (بدهی‌ها به شخص وصل‌اند؛ نام‌های قبلی بدهی‌ها خودکار به شخص تبدیل شدند)، اهداف پس‌انداز به‌صورت «پاکت» (پول در حساب‌ها می‌ماند)، با پیش‌بینی زمان رسیدن و مبلغ لازم ماهانه، دنگ (تقسیم مساوی دقیق تا ریال، پیشنهاد تسویه با کمترین انتقال، ثبت سهم خودم به‌عنوان هزینه و سهم بقیه به‌عنوان قرض).
- **فاز ۳:** انجام شد. وام و اقساط (جدول اقساط شمسی، پرداخت = تراکنش «قسط و وام»، لغو پرداخت)، بدهی و طلب (پرداخت جزئی، با یا بدون حساب؛ نوع تراکنش `DEBT` که موجودی را جابه‌جا می‌کند ولی درآمد/هزینه حساب نمی‌شود)، یادآور روزانه با یک آلارم نادقیق (بدون سرویس و WorkManager)، موتور قوانین با شرط‌های متن/بانک/نوع/بازه مبلغ و عمل «دسته بزن» یا «نادیده بگیر». Notification Listener ساخته نشد چون هر دو بانک کاربر پیامک می‌فرستند.
- **فاز ۲:** انجام شد. دریافت پیامک، صف بررسی، تأیید همه، حذف تکراری، تطبیق مانده و تعدیل، اسکن ۳ ماه اخیر، قانون «توضیح ← دسته». هنوز نیست: اعلان سیستمی برای پیامک جدید (عمداً؛ نشان روی صفحه خانه کافی است)، صفحه «ساخت الگو از نمونه».

## ۹. موارد باز و ریسک‌ها

- **پیامک بانک‌ها:** کامل. کشاورزی (`KESHAVARZI`) و بلو (`09999987641`)، هر دو پیامک، تست‌شده روی ۶ نمونه واقعی. Notification Listener برای این دو بانک لازم نیست.
- **ماژول ۹ (طلا/ارز):** تصمیم کاربر: فعلاً نه. صفحه خانه «موجودی کل» (جمع حساب‌ها) نشان می‌دهد، نه «مجموع دارایی».
- **فرمول اقساط:** با جدول واقعی credino.net تست شد (سپینو ۱۷۵ میلیون تومان ۲۳٪ ۲۴ قسط ← ۹٬۱۶۵٬۴۰۰ تومان؛ کارمزد ۴٪ ۳۶ قسط ← ۹٬۰۹۰٬۹۰۹ تومان). جدول طرح‌ها داخل اپ است (`BankPlans.all`) و از فرم «وام جدید» با دکمه «انتخاب» قابل استفاده است. اقساط کارمزدی یکسان نیستند؛ اپ فقط «قسط رایج» را ذخیره می‌کند و جدول اقساط را یکسان می‌سازد (اختلاف چند درصدی در جمع بازپرداخت).
- سیاست بازار و مایکت درباره دسترسی پیامک قبل از انتشار بررسی شود.
