# قالب پیامک بانک‌ها

نمونه‌های خام در `sms-samples.txt` هستند (خصوصی و در `.gitignore`). الگوهای زیر روی هر ۶ نمونه تست شده‌اند. این موارد همه درست درآمدند:
- تشخیص بانک از روی فرستنده
- نوع تراکنش، مبلغ، مانده و تاریخ و ساعت
- کارت یا شماره حساب، و توضیح
- تشخیص پیام تکراری

| بانک | فرستنده | نوع پیام |
|---|---|---|
| کشاورزی | `KESHAVARZI` | پیامک (فقط برداشت و واریز؛ پیامک خرید یا انتقال ندارد) |
| بلو | `09999987641` | پیامک |

هر دو بانک با **پیامک** کار می‌کنند، پس برای این دو بانک Notification Listener لازم نیست و همان‌طور که برنامه‌ریزی شده، پیش‌فرض خاموش می‌ماند.

## تشخیص بانک

1. **فرستنده** (روش اصلی). شماره‌ها قبل از مقایسه یکسان می‌شوند: `+989999987641`، `09999987641` و `9999987641` همه به `9999987641` تبدیل می‌شوند (۱۰ رقم آخر). اسم فرستنده‌هایی مثل `KESHAVARZI` بدون حساسیت به حروف کوچک و بزرگ مقایسه می‌شود.
2. **امضای متن** (پشتیبان، برای وقتی بانک فرستنده را عوض کند): `bki. ir` برای کشاورزی، و «به حساب شما نشست» یا «از حساب شما پرید» برای بلو.

پیامک هر فرستنده دیگری **همان اول رد می‌شود** و هیچ پردازشی رویش انجام نمی‌شود. این برای مصرف باتری مهم است.

## نرمال‌سازی متن (قبل از اجرای الگوها)

1. ارقام فارسی و عربی به انگلیسی تبدیل می‌شوند؛ `ي ك` به `ی ک`.
2. نیم‌فاصله به فاصله تبدیل می‌شود.
3. جداکننده هزارگان بین دو رقم (`,` و `٬`) حذف می‌شود.
4. فاصله‌های اول و آخر هر خط حذف می‌شود.

## قالب فایل: `assets/banks/<bank>.json`

قالب **فیلدی** است، یعنی هر فیلد الگوی خودش را دارد. این‌طوری اگر بانک ترتیب خطوط را عوض کند، چیزی خراب نمی‌شود.

### بانک کشاورزی

```
برداشت322,000          ← نوع + مبلغ (ریال)، بدون فاصله
مانده100,186,745       ← مانده بعد از تراکنش
050807-09:48           ← تاریخ شمسی YYMMDD + ساعت ⇒ ۱۴۰۵/۰۸/۰۷ ۰۹:۴۸
کارت9829*              ← ۴ رقم آخر کارت (در برداشت)
229872836              ← شماره حساب (در واریز پایا، به‌جای کارت)
bki. ir
```

```json
{
  "bank": "keshavarzi", "name": "بانک کشاورزی", "unit": "RIAL",
  "detect": { "senders": ["KESHAVARZI"], "signature": "bki\\.\\s?ir" },
  "kinds": [
    { "pattern": "^واریز", "type": "INCOME" },
    { "pattern": "^برداشت", "type": "EXPENSE" }
  ],
  "fields": {
    "amount":  "^(?:برداشت|واریز)[^\\d\\n]*(\\d+)",
    "balance": "^مانده\\s*(\\d+)",
    "datetime": { "pattern": "^(\\d{2})(\\d{2})(\\d{2})-(\\d{2}):(\\d{2})$", "order": "yMdHm", "yearBase": 1400 },
    "card4":   "کارت\\s*(\\d{4})\\*",
    "account": "^(\\d{6,})$"
  }
}
```

- الگوی مبلغ هر نوع واریزی را می‌گیرد: «واریز»، «واریز پایا»، «واریز ساتنا» و… (با یک نمونه ساختگی ساتنا هم تست شد).
- عدد `229872836` در واریز پایا اول با شماره حساب‌های ثبت‌شده تطبیق داده می‌شود؛ اگر جور نبود، به‌عنوان شماره پیگیری ذخیره می‌شود.

### بلو

```
واریز پول                                              ← عنوان (برای تشخیص لازم نیست)
محمدجواد عزیز، 44,000,000ریال به حساب شما نشست.        ← «نشست» = واریز
محمدجواد عزیز، 200,000 ریال بابت خرید شارژ از حساب شما پرید.   ← «پرید» = برداشت، «بابت …» = توضیح
موجودی: 94,251,651 ریال
۱۴:۰۶
۱۴۰۵.۰۸.۰۶
```

```json
{
  "bank": "blu", "name": "بلو", "unit": "RIAL",
  "detect": { "senders": ["09999987641"], "signature": "(به حساب شما نشست|از حساب شما پرید)" },
  "kinds": [
    { "pattern": "نشست", "type": "INCOME" },
    { "pattern": "پرید", "type": "EXPENSE" }
  ],
  "fields": {
    "amount":  "(\\d+)\\s*ریال\\s*(?:به حساب|بابت|از حساب)",
    "balance": "موجودی:\\s*(\\d+)\\s*ریال",
    "description": "بابت (.+?) از حساب",
    "datetime": { "pattern": "^(\\d{2}):(\\d{2})\\s+(1[34]\\d{2})\\.(\\d{2})\\.(\\d{2})$", "order": "HmyMd", "fallback": "RECEIVED_AT" }
  }
}
```

- پیام بلو **شماره کارت یا حساب ندارد**. اگر کاربر فقط یک حساب بلو داشته باشد، تراکنش خودکار به همان وصل می‌شود؛ وگرنه در صف بررسی حساب پرسیده می‌شود.
- «بابت خرید شارژ» با یک قانون پیش‌فرض به دسته «شارژ و اینترنت» می‌رود.
- اسم کاربر در پیام («محمدجواد عزیز») هیچ‌جا استفاده یا ذخیره نمی‌شود، چون فقط فیلدها استخراج می‌شوند.

## تشخیص تکرار

کلید تکرار = `hash(bank + متن نرمال‌شده)`. دو پیام آخر بلو در نمونه‌ها دقیقاً یکی‌اند و یکی‌شان حذف می‌شود. دو برداشت واقعی با مبلغ یکسان هیچ‌وقت کلید یکسان نمی‌گیرند، چون **مانده**شان فرق دارد.

## تطبیق مانده (پیاده‌شده در فاز ۲)

بعد از تأیید هر پیامک، اپ آخرین مانده‌ای که بانک برای هر حساب اعلام کرده را با موجودی خود برنامه در همان لحظه مقایسه می‌کند (`JDao.balanceChecks`).

- **برابر** ← هیچ پیامی نشان داده نمی‌شود.
- **نابرابر** ← کادر زرد «موجودی با بانک جور نیست» با هر دو عدد و دکمه «ثبت تعدیل». تعدیل یک تراکنش `ADJUST` با همان اختلاف و در همان زمان است، پس بعد از ثبت، مقایسه برابر می‌شود.

این روش هم پیامک جاافتاده را می‌گیرد و هم خطای موجودی اولیه‌ای که کاربر دستی وارد کرده.

## امتیاز اطمینان

`۶۰` + حساب از روی کارت یا شماره حساب `۲۵` (یا تنها حساب آن بانک: `۲۰`، و اگر پیامک کارتی داشت که ثبت نشده: `۱۲`) + تاریخ در متن `۵` + مانده `۵` + شناسایی از روی فرستنده `۵`، حداکثر `۹۹`.
«تأیید همه» فقط موارد `≥ ۹۰` با حساب مشخص را تأیید می‌کند.

## تست‌ها (`SmsParserTest`، همه پاس)

- هر ۶ نمونه، با خروجی‌های بالا (نمونه‌ها **ناشناس‌شده**، یعنی اسم و عددها عوض شوند ولی قالب دست نخورد)
- ۳ شکل نوشتن شماره فرستنده بلو
- واریز ساتنا کشاورزی
- پیامک رمز پویا و تبلیغاتی از همین فرستنده‌ها باید نادیده گرفته شود (نمونه واقعی ندارم؛ هر پیامی که مبلغ و مانده نداشته باشد، رد می‌شود)

## افزودن بانک جدید

1. حداقل یک نمونه از هر نوع پیامی که آن بانک می‌فرستد
2. شماره یا اسم فرستنده
3. یک فایل JSON مثل بالا + تست با همان نمونه‌ها
